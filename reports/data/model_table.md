RAM columns are measured, not estimated: for each resolution a fresh Python subprocess (CPU only, torch 2.6.0+cu118, torch.set_num_threads(4) to match the 4-core Raspberry Pi 4) imports torch and the model definitions (app/inference.py), then records VmRSS from /proc/self/status as the baseline; VmHWM was reset to the baseline RSS via /proc/self/clear_refs before building the model. It then builds the model, loads the checkpoint (state dict freed after loading), runs 5 forwards in torch.inference_mode on a float32 (1, 1, r, r) input and records VmHWM. `RAM_peak_MB` = overall peak VmHWM (build, load and forwards) minus baseline VmRSS; at batch 1 up to r256 it is set by weight loading (model plus the transient state dict copy), so it barely depends on resolution. `RAM_forward_MB` = peak increase during the forward passes only: after loading, VmHWM is reset again and the column is VmHWM after the forwards minus VmRSS before them; this is the activation/workspace part that scales with resolution.
